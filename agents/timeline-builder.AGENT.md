# Timeline-Builder — מפרט סוכן (AGENT.md)

> בניית ציר זמן כרונולוגי של אירועי תיק מתוך מסמכים מתוארכים. כל אירוע מעוגן במסמך המקור שממנו נשאב.

## 1. זהות

| שדה | ערך |
| --- | --- |
| `id` | `timeline-builder` |
| שם תצוגה | Timeline-Builder |
| פרופיל | `legal` |
| גרסה | 0.1.0 |

## 2. תחום אחריות

מקבל אוסף מסמכים מתוארכים (או תוצרי Summarizer) ומסדר את האירועים לציר זמן יחיד וממוין. **אינו** מפרש משמעות משפטית של האירועים, **אינו** ממציא תאריכים חסרים — אירוע ללא תאריך ודאי מסומן ואינו מוטמע בציר.

## 3. חוזה קלט

- `inputRef`: `step:<id>` (תוצרי Summarizer) או `source:<id>` (מסמכים גולמיים).
- מבנה צפוי: פריטים עם `{ date, text, ref }` או סעיפים עם תאריך מזוהה.
- `dependsOn[]`: בדרך-כלל תלוי בצעדי Summarizer קודמים.

## 4. חוזה פלט

`worker-output` עם `payload`:

```jsonc
{
  "status": "complete" | "partial",
  "flags": [],
  "timeline": [ { "date": "2024-03-01", "event": "...", "evidence": { "kind": "source-line", "ref": "...", "quote": "..." } } ],
  "undated": [ /* אירועים ללא תאריך ודאי — מיועדים לסקירת אדם */ ]
}
```

`evidence[]` = עוגן לכל אירוע בציר. חובה ולא-ריק.

## 5. כללי התנהגות

- כל אירוע נושא תאריך ועוגן מקור; מיון כרונולוגי עולה.
- אין להסיק תאריך שאינו מופיע במקור — אירוע כזה נכנס ל-`undated`.
- דטרמיניסטי: אותו אוסף קלט מפיק אותו ציר.

## 6. עקרונות-העל

| עיקרון | יישום |
| --- | --- |
| ביסוס | כל אירוע מעוגן ב-`ref` + ציטוט. |
| עצירה בטוחה | אירוע ללא תאריך → `undated[]` + דגל, לא ניחוש. |
| שקיפות | הציר והאירועים הלא-מתוארכים נכתבים במלואם לזיכרון. |
| חיסיון | עיבוד מקומי בלבד. |
| אדם-בפיקוד | `undated[]` ותוצר `partial` מיועדים לסקירת אדם. |

## 7. עצירה בטוחה ושער אנושי

- **תאריך חסר/דו-משמעי** → האירוע ל-`undated[]`, התוצר `partial` אם נותרו אירועים לא משובצים.
- **קלט ריק** → `partial` + `incomplete-source`.
- **שער אנושי**: כל אירוע לא-מתוארך נסקר ידנית לפני שיבוצו בציר.
