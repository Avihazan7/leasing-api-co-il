# שלב א' — הוכחת היתכנות רב-סוכנית · Factum IL

> מימוש רץ של השלב הראשון בשכבת הרב-סוכנים: מנהל אחד, עובד אחד, וזיכרון משותף.
> זוהי הוכחת היתכנות בסיכון מינימלי — אם השלב הזה עובד, כל השאר הוא הרחבה.

## מה השלב הזה מוכיח

שלושה דברים, מקצה לקצה:

1. **תכנון וניתוב** — המנהל מקבל משימה, מפרק אותה לתוכנית מובנית, וכותב אותה לזיכרון המשותף. הוא אינו מבצע בעצמו.
2. **ביצוע דרך הזיכרון** — העובד קורא את תת-המשימה מהזיכרון המשותף, מבצע אותה לפי חוזה ה-AGENT.md שלו, וכותב תוצר מעוגן חזרה. העובד אינו מודע למנהל ואינו מודע לעובדים אחרים.
3. **ממשל אכוף** — תקרת צעדים, יומן append-only מלא, ושדה `evidence[]` חובה. הממשל נאכף בקוד, לא רק מתועד.

## מבנה הקבצים

```
stage-a/
├── run-stage-a.js            # מריץ ההוכחה מקצה לקצה
└── src/
    ├── shared-memory.js      # אפיק הזיכרון המשותף (append-only, אוכף evidence)
    ├── manager.js            # סוכן המנהל (מתכנן ומנתב, תקרת צעדים)
    └── worker-summarizer.js  # סוכן עובד (Summarizer, סיכום מעוגן-מקור)
```

## הרצה

```bash
node run-stage-a.js
```

ההרצה מדפיסה חמישה שלבים: תכנון, ביצוע, הרכבת פלט סופי, היומן המלא, ואימות מנגנוני הממשל.
אין תלויות חיצוניות — הכול רץ מקומית על Node.js בלבד (חיסיון).

## תוצאת ההרצה — חמשת מנגנוני הממשל מאומתים

```
[✓] evidence[] mandatory on worker output     : ENFORCED
[✓] step ceiling halts runaway loops          : ENFORCED
[✓] worker safe-stops on missing input        : ENFORCED
[✓] memory is append-only (full audit)        : ENFORCED
[✓] partial output flagged for human review   : ENFORCED
```

כל בדיקה מַפעילה את המנגנון בפועל (מנסה להפר אותו ומוודאת שההפרה נחסמת) — אכיפה בקוד, לא רק תיעוד.

## ההתאמה לאפיון

המימוש נאמן לחוזי-הליבה שהוגדרו במסמך אפיון שכבת הרב-סוכנים:

- **חוזה המנהל** — `taskId`, `goal`, `steps[]` (כל אחד עם `stepId`, `worker`, `dependsOn[]`, `inputRef`), ו-`maxSteps`.
- **רשומת זיכרון משותף** — `entryId`, `taskId`, `author`, `stepId`, `payload`, `evidence[]`, `ts`. append-only.
- **חמשת עקרונות-העל** — ביסוס (evidence חובה), עצירה בטוחה (דגלי `incomplete-source`), שקיפות (יומן מלא), חיסיון (הכל מקומי, אפס תלות חיצונית), ואדם-בפיקוד (פלט `partial` מיועד לסקירה).

## הצעד הבא — שלב ב'

המבנה כבר תומך בהרחבה בלי שינוי ארכיטקטוני:

- **ריבוי עובדים** — מילון ה-`workers` כבר מאפשר רישום של Timeline-Builder ו-Contract-Review לצד ה-Summarizer. הוספתם אינה דורשת שינוי במנהל או בזיכרון.
- **תלות בין צעדים** — שדה `dependsOn[]` ומנגנון `_resolveInput` כבר קיימים; עובד תלוי יקרא מתוצרי קודמיו בזיכרון.
- **סוכן סוקר** — שלב ג' יוסיף Reviewer שבוחן את המכלול לפני מסירה.

עיקרון מנחה: אנו מרחיבים את אותה תשתית, לא בונים חדשה. שלב א' הוכיח שהתשתית עובדת.
