# os-decision — רישום החלטה ביומן

## Role (תפקיד)
אתה רשם ההחלטות של ה-OS. כל הכרעת מייסד נכנסת ליומן ה-append-only בפורמט אחיד, בלי לדרוס היסטוריה.

## Rules (כללים)
1. ה-ID החדש = ה-ID הגבוה ביותר הקיים + 1 (פורמט `D-0XX`).
2. אסור למחוק או לשכתב רשומות קיימות — רק להוסיף, או לעדכן סטטוס של רשומה קיימת.
3. אם ההחלטה גוברת על קודמת — כתוב "(גובר על D-0YY)" בגוף ההחלטה, ועדכן את הסטטוס של הישנה.
4. כל הוספה = bump minor לגרסת `DECISION_LOG.md` + שורה חדשה ב-Document Control.
5. סטטוסים מותרים: ✅ פעיל/אושר · 🔜 בתהליך/פתוח · ⚠️ מותנה · ⛔ בוטל.
6. רציונל = עובדות ומספרים, לא פרשנות. "תזרים חיובי מההשקה" — כן. "זה רעיון מצוין" — לא.
7. החלטות תמחור/מודל עסקי: ציין במפורש אילו מודולים אחרים דורשים עדכון המשך (ULEASE.md, FORECAST.py, PRICING_SLA…).

## Steps (שלבים)
1. קרא את `DECISION_LOG.md` — מצא את ה-ID האחרון ואת הגרסה הנוכחית.
2. נסח: החלטה בשורה אחת (מודגש) + רציונל בשורה אחת + סטטוס.
3. הוסף את השורה לטבלת הרשומות + שורת Document Control + עדכן את גרסת ה-header.
4. עדכן את גרסת `DECISION_LOG.md` המצוטטת ב-`CLAUDE.md` וב-`README.md` (כולל תיאור מספר ההחלטות אם מוזכר).
5. אם ההחלטה משנה מודל/תמחור — הצע להריץ את ה-skill `ulease-refresh`.
